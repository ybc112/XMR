合约安全与逻辑审计

已确认的优势

  • 使用 OpenZeppelin SafeERC20、ReentrancyGuard、Ownable，代码基础扎实
  • 管理员与所有者权限分离：日常操作（结算、价格）用 admin，参数与所有权操作用 owner
  • 所有资金转移均通过 safeTransfer，避免部分 ERC20 异常
  • 重入保护覆盖 invest、claim、闪兑、提现、processXMRWithdrawal
  • 黑名单用户仍可提现，符合 DeFi 安全惯例（防止资金被锁）
  • 紧急暂停保留提现通道，避免极端情况下用户资金无法取出
  • 静态收益封顶 30 天，防止长期未领取导致巨额一次性发放

需关注的风险与建议

已修复：出局后未提现收益清零

需求文档原文："订单结束后，需要在原点进行复投...出局后未提现的收益直接清零。"

合约 invest 的出局复投分支现已清空 pendingUSDT / pendingXMR / xmrWithdrawalPending，测试用例 6.6 与 coverage 测试已更新并验证通过。

已优化：资金提取函数增加余额校验

processXMRWithdrawal 增加合约 XMR 余额校验；withdrawFees 与 withdrawToken 增加目标地址非零、金额大于 0、合约余额充足等校验，避免无效交易和 revert 信息不明确的问题。

已优化：setWithdrawFee 增加事件

参数设置均限制不超过 100%，且 setWithdrawFee 现已发出 WithdrawFeeUpdated 事件，便于前端与事件扫描器追踪。

中风险：processXMRWithdrawal 依赖合约 XMR 储备

虽然已增加余额校验，但合约仍需持有足额 XMR 才能处理提现。建议 Admin 面板持续监控合约 XMR 余额，必要时由 owner 通过 withdrawToken 或手动转入补充。

  • 支持钱包连接、USDT 授权、投资、领取静态收益、闪兑、提现、管理员操作

  • 资产页面增加总资产估值、闪兑快捷入口、XMR 提现处理中状态

后端

  • Express API 覆盖用户查询、事件扫描、管理员操作、多签查询、等级信息
  • 事件扫描器缓存 19 类合约事件，支持分页查询
  • 管理路由使用 admin-key 认证，交易使用管理员私钥签名
  • 建议：生产环境应将 admin-key 改为更安全的签名/时间戳机制或 JWT
  • 建议：事件扫描起始区块应配置为实际部署区块，避免从 0 扫描造成性能问题

最终建议清单

  1. 部署前替换合约地址占位符：frontend/src/config/contracts.js 与 backend/.env 中的占位地址需替换为真实部署地址。
  2. 配置管理员私钥与 admin-key：backend/.env 中 ADMIN_PRIVATE_KEY 与 ADMIN_API_KEY 需设置为真实值。
  3. 验证多签流程：部署后将 StakingDApp 与 XMRToken 的 owner 转移到 MultiSigWallet。
  4. 配置事件扫描起始区块：backend/.env 中 START_BLOCK 设为实际部署区块。
  5. 生产安全加固：后端认证机制升级，避免使用单一静态 key。
  6. 补充前端错误降级：当前未连接钱包时控制台会输出合约调用失败，建议增加更优雅的未连接状态提示，减少控制台噪音。
